# Multi-AZ Runner Subnets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let runner launches use every standard AZ in the region, retrying the next AZ on a zonal refusal, and stop retrying a job whose launches keep failing.

**Architecture:**
- The existing single-subnet `ec2.Vpc` stays exactly as it is.
- The stack adds a `10.1.0.0/16` secondary CIDR plus one public `/21` subnet per extra AZ, each keyed by its AZ letter. All subnet IDs reach the webhook and reconciler Lambdas as `SUBNET_IDS`.
- `launchRunner` loops `RunInstances` over those subnets.
- The reconciler counts failed launches toward `reconciler-max-top-ups`.

**Tech Stack:** TypeScript, AWS CDK v2 (`aws-cdk-lib/aws-ec2`), AWS SDK v3, Jest.

**Spec:** `docs/superpowers/specs/2026-10-29-multi-az-design.md`

## Global Constraints

- The `ec2.Vpc` construct (`RunnerVpc`, `maxAzs: 1`, one `public` subnet) must not change. Subnet 1 keeps logical ID `RunnerVpcpublicSubnet1Subnet740263F6` and CIDR `10.0.0.0/16`.
- Secondary CIDR is `10.1.0.0/16`, fixed, with no override.
- An extra subnet's CIDR is `10.1.<8 × letterIndex>.0/21`, where `letterIndex` is the AZ's last letter (`a`=0 … `z`=25). Its construct ID is built from the letter, never from list position.
- Only AZs matching `^<region>[a-z]$` are used. Synth never throws when no extra AZs remain.
- Zonal refusal codes (try the next subnet): `InsufficientInstanceCapacity`, `UnfulfillableCapacity`, `SpotMaxPriceTooLow`, `Unsupported`.
- `CAPACITY_ERROR_CODES` and `isSpotCapacityError` in `lambda/shared/spot.ts` stay unchanged.
- No IAM changes. No new SSM parameters. Webhook handler code does not change.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Upgrading an existing deployment must leave subnet 1's logical ID and CIDR as they are. Task 3 pins this in a test.
2. A `SUBNET_IDS` with a single entry, or with stray spaces or empty entries, must still launch. Task 1 pins this.
3. When a Spot launch gets mixed refusals (`Unsupported` in one AZ, capacity in another), it must wait (`SpotCapacityError`), not fail. Task 1 pins this.
4. An opted-in Local Zone in the AZ list must not get a subnet. Task 3 pins this.
5. A failed launch on a row that was deleted mid-pass must not log an error. Task 2 pins this.

`launcher.ts`, `launchRunner`:
- Build the `RunInstancesCommand` input once, with `SubnetId` varying per attempt.

- Log each zonal refusal with the subnet ID and the error code.

Decision logic:

```
for each subnet in order:
  try → return instance id
  catch e:
    if isZonalRefusal(e): refusals.push(e); log; continue
    if spot && isSpotCapacityError(e): delete JIT, throw SpotCapacityError   // MaxSpotInstanceCountExceeded
    throw e
// every subnet refused
if spot && refusals.some(isSpotCapacityError): delete JIT, throw SpotCapacityError
throw refusals[refusals.length - 1]
```

Pull the existing "delete JIT, then build `SpotCapacityError`" block into one local helper so both throw sites use it. Keep its error logging and message as they are.
